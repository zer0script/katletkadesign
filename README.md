# katletkadesign

Портфолио дизайнера: публичный статический сайт на GitHub Pages (`https://damnwu.github.io/katletkadesign/`)
и отдельный **локальный** редактор контента. Редактора в опубликованном сайте нет.

```
локальный редактор → content/ (JSON + картинки) → git commit/push → GitHub Actions → dist/ → GitHub Pages
```

## Структура

| Путь | Что это |
| --- | --- |
| `content/content.json` | весь редактируемый контент: тексты, Telegram, папки, работы, прайс |
| `content/assets/works/` | картинки работ |
| `site/` | исходники публичного сайта (`index.template.html`, `site.css`, `main.js`, `glyphs.js`, `static/`) |
| `shared/schema.js` | проверка и нормализация контента, экранирование (общий для сайта, сборки, редактора) |
| `editor/` | локальный редактор: сервер (`editor/server/`) и страница (`editor/public/`) |
| `scripts/` | сборка, проверки, просмотр, запуск редактора |
| `tests/` | тесты (`node:test`) |
| `.github/workflows/` | `pages.yml` — публикация, `ci.yml` — проверка без публикации |

Зависимостей нет: нужен только **Node.js 20+** (в CI используется 22). `npm install` не требуется.

## Команды

| Команда | Действие |
| --- | --- |
| `npm run edit` | запустить локальный редактор — `http://127.0.0.1:4174/` |
| `npm run build` | собрать сайт в каталог `dist/` |
| `npm run preview` | показать собранный сайт: `http://127.0.0.1:4173/katletkadesign/` |
| `npm run validate` | проверить `content.json` и наличие картинок |
| `npm run check` | проверить, что в `dist/` нет редактора, auth и битых ссылок |
| `npm run verify` | validate + build + check |
| `npm test` | тесты |

Порт можно сменить: `PORT=4180 npm run edit`.

## Как поменять работу или цену

1. `npm run edit`, открыть `http://127.0.0.1:4174/`.
2. Вкладки: **Тексты** (первый экран, нижний текст, Telegram), **Папки и работы** (создать, переименовать, удалить, сортировать папки и работы, загрузить или заменить картинку), **Прайс** (заголовок, позиции: название, коротко, цена, полная информация, порядок).
3. Нажать **Сохранить в файлы** (или Ctrl+S). Редактор пишет только `content/content.json` и `content/assets/works/`. Картинки сжимаются в браузере до WebP (до 1600 px) и загружаются на локальный сервер, имя файла назначает сервер. Картинки, на которые больше никто не ссылается, удаляются при сохранении.
4. Несохранённые правки хранятся как черновик в `localStorage` самого редактора и не влияют на сайт, пока вы не нажмёте «Сохранить в файлы».
5. Проверить: `npm run verify && npm run preview`.
6. Закоммитить и отправить: `git add content && git commit -m "Обновил контент" && git push`.

Публичный сайт показывает только то, что лежит в `content/` в репозитории: черновиков, IndexedDB и localStorage он не читает.

## Публикация

`.github/workflows/pages.yml` запускается при push в `main` и вручную (`workflow_dispatch`). Задача `build` (права `contents: read`) прогоняет тесты, `npm run verify` и загружает **только `dist/`** штатным `actions/upload-pages-artifact`. Задача `deploy` (права `pages: write`, `id-token: write`) публикует артефакт через `actions/deploy-pages`. Для pull request работает только `ci.yml` с правом чтения, публикации там нет.

### Ручные настройки GitHub (один раз)

1. Репозиторий → **Settings → Pages → Build and deployment → Source: GitHub Actions** (сейчас, вероятно, выбран «Deploy from a branch»).
2. **Settings → Environments → github-pages**: при желании ограничить ветки деплоя правилом «только `main`».
3. После первого push проверить вкладку **Actions** и открыть сайт.

Сайт живёт по пути `/katletkadesign/`, поэтому в сборке только относительные ссылки (`site.css`, `js/…`, `assets/works/…`, `media/intro.mp4`). `npm run check` отклоняет абсолютные пути от корня домена.

## Безопасность и что именно публикуется

- В `dist/` попадают `index.html`, `site.css`, три JS-модуля сайта (`js/site/main.js`, `js/site/glyphs.js`, `js/shared/schema.js`), `ice.webp`, `media/intro.mp4`, картинки из `content.json` и лицензия шрифта. Модули выбираются обходом графа импортов от `site/main.js`; код редактора не импортируется публичной точкой входа, поэтому физически не может попасть в сборку.
- `npm run check` проверяет состав артефакта (белый список файлов, ни `editor/`, ни `scripts/`, ни `*.map`), граф модулей, отсутствие редакторской разметки и кода (форм, `setEdit`, PBKDF2, IndexedDB, экспорт HTML), отсутствие `auth` и служебных полей в данных, существование каждой картинки и локальной ссылки.
- Схема `content.json` строгая: неизвестные поля, а также `auth`, `password`, `hash`, `token` и т. п. отвергаются. Картинки только `assets/works/*.webp|jpg|png|avif`, Telegram только `https://t.me/…`. Весь текст при выводе экранируется.
- Локальный редактор: слушает только `127.0.0.1`; проверяет `Host` и `Origin`; все запросы к API требуют случайный токен, создаваемый при каждом запуске; тело JSON ≤ 1 МБ, картинка ≤ 8 МБ; формат картинки определяется по содержимому; имена файлов назначает сервер; запись только в `content/content.json` и `content/assets/works/`. Ключей и токенов GitHub в браузерном коде нет.
- **Опубликованный сайт нельзя изменить через консоль браузера**: правка DOM или переменных в консоли меняет только страницу в браузере посетителя. Файлы на хостинге меняются только новой публикацией из `main` через GitHub Actions, а это требует прав на запись в репозиторий.
- Исходники редактора лежат в репозитории и могут быть видны, если репозиторий публичный. Это не даёт прав: публиковать может только тот, кто может сделать push в `main`. Защитой служат права доступа к репозиторию, а не скрытность кода.
- Старый встроенный редактор (код доступа и его хеш) остаётся в **истории git**. Если код где-то ещё используется, смените его; в новой версии кода доступа нет.

## Тесты

`npm test` проверяет схему контента, сборку и проверку артефакта (в том числе что проверка действительно ловит подброшенный редактор, source map, `auth`, битые ссылки) и сервер редактора: сохранение правок работы и цены в файлы, создание, переименование, сортировку и удаление раздела, загрузку и очистку картинок, отказ при неверном токене, `Origin`, `Host`, типе и размере, защиту от выхода за разрешённые каталоги.

## Лицензии

Контуры букв заголовка получены из шрифта Unbounded (SIL OFL), лицензия: `site/OFL-Unbounded.txt`, копия попадает в `dist/`.
